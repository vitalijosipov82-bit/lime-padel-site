# DESIGN.md · Падел-клуб в Казани

Версия 1.0. Обязательная спецификация сайта. Значения в таблицах применяются ко всем страницам и состояниям. Новый токен, компонент или тип движения сначала добавляется в этот документ, затем в проект.

Первый экран показывает клуб, объясняет, где он находится, и открывает путь к бронированию. Главный CTA — **«Забронировать корт»**. Тон сайта — спортивный, собранный и гостеприимный. Премиальность строится на съёмке реального пространства, крупном наборе и свободных полях. Название, адрес, количество кортов, цены и доступность берём из подтверждённых данных клуба.

## 1. Стек

| Слой | Обязательный выбор |
| --- | --- |
| Разметка | Семантический HTML5. Ссылки для переходов, кнопки для действий, нативные элементы форм и диалогов. Основной контент и переход к бронированию доступны из HTML. |
| Стили | CSS Custom Properties для токенов, CSS Grid для сетки, Flexbox для элементов внутри компонентов. Тема задаётся на корневом элементе. |
| Логика | Vanilla JavaScript, ES modules. GSAP 3, ScrollTrigger и Lenis 1.3. Фиксируем точные версии зависимостей в lock-файле при инициализации проекта. |
| Движение | GSAP управляет таймлайнами и состояниями из раздела 4. ScrollTrigger связывает сцены с позицией страницы. Lenis сглаживает вертикальную прокрутку колёсиком. |

Используем оконный скролл и CSS Lenis. Параметры Lenis — `autoRaf: false`, `smoothWheel: true`, `syncTouch: false`, `lerp: 0.12`, `wheelMultiplier: 1`, `infinite: false`, `anchors: true`. Один цикл кадров через `gsap.ticker`. Передаём в `lenis.raf` время в миллисекундах, на событие `scroll` вызываем `ScrollTrigger.update`, выставляем `gsap.ticker.lagSmoothing(0)`. `ScrollTrigger.refresh()` вызываем после готовности шрифтов и фактических изменений геометрии секций. CSS `scroll-behavior` — `auto`. Якорный отступ равен высоте шапки плюс 16 px.

Lenis включается при ширине от 1024 px, точном указателе, доступном hover и обычной настройке движения. В остальных случаях работает нативный скролл. При смене этих условий очищаем GSAP-контекст, обработчики и экземпляр Lenis, затем применяем подходящий режим. Открытый диалог останавливает фон и сохраняет нативный скролл внутри себя.

Справка по интеграции: [Lenis](https://github.com/darkroomengineering/lenis#gsap-scrolltrigger), [ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/), [gsap.matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia%28%29/).

- Hero и секция «Внутри клуба» используют тёмные токены в обеих темах. За текстом Hero непрозрачность подложки `#101A17` составляет минимум 72%. Поверх фото используем `--text` и `--accent`. Для мелких подписей на фото действует тот же порог контраста, что и для основного текста.
- Для всего читаемого текста целевой минимум **4,5:1**, для значимых границ, иконок и кольца фокуса — **3:1** к соседнему фону. Проверенные минимумы для сплошных токенов в тёмной и светлой темах соответственно: вторичный текст **7,93:1 / 6,18:1**, текст CTA во всех трёх состояниях **10,91:1 / 7,94:1**, граница контрола **4,04:1 / 3,87:1**. Контраст на фактических медиа проверяем при приёмке. [W3C: контраст текста](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C: контраст элементов интерфейса](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- Фокус — контур 2 px с отступом 3 px. Текстовые ссылки подчёркнуты. Активная вкладка обозначена цветом и линией 2 px. Ошибка и успех обозначены текстом, рядом с соответствующим полем или действием.

Подключаем variable WOFF2 из Google Fonts локально, с кириллицей и латиницей, `font-display: swap`. Резерв для Oswald — `Arial Narrow`, затем `Arial`, для Manrope — `system-ui`, затем `Arial`. ## 4. Правила анимации

Все значения `duration`, `delay` и `stagger` даны в секундах. `delay` отсчитывается от запуска события или таймлайна, указанного в строке. Для открытия и закрытия меню используются отдельные фазы. При смене состояния во время движения продолжаем от текущих значений с `overwrite: 'auto'`. Для `hover` на тач-устройствах используем только состояние нажатия, фокус клавиатуры всегда отображается сразу.

| Событие | Изменение | `duration` | `delay` | `ease` | `stagger` |
| --- | --- | ---: | ---: | --- | ---: |
| Hero, один раз на загрузку страницы | Маска медиа `inset(0 8% 0 0)` → `inset(0)` | 0,64 | 0 | `power3.out` | 0 |
| Hero, тот же таймлайн | H1 из `y: 18` и `opacity: 0` в `y: 0` и `opacity: 1` | 0,50 | 0,10 | `power3.out` | 0 |
| Вход секции | Декоративное медиа или второстепенная группа карточек из `y: 16` и `opacity: 0` | 0,42 | 0 | `power2.out` | 0,06, до 3 элементов |
| CTA, вход / выход hover | Заливка `accent` ↔ `accent-hover`, стрелка `x: 0` ↔ `x: 3`, рамка кнопки сохраняет размер | 0,16 / 0,18 | 0 | `power2.out` | 0 |
| CTA, нажатие / отпускание | Заливка → `accent-pressed` → актуальное состояние | 0 / 0,12 | 0 | `none` / `power2.out` | 0 |
| Карточка, вход / выход hover | Внутреннее фото `scale: 1` ↔ `1.025`, стрелка `x: 0` ↔ `x: 4` | 0,22 / 0,20 | 0 | `power2.out` | 0 |
| Вкладка «Первый визит» | Текст и активное состояние меняются сразу. Индикатор перемещается к выбранной вкладке | 0 / 0,22 | 0 | `none` / `power2.out` | 0 |
| Фото вкладки | Новое фото накладывается на предыдущее, `opacity: 0` → `1` | 0,32 | 0 | `power2.out` | 0 |
| Меню, открытие | Затемнение `opacity: 0` → `0.56`, панель `y: -12` → `0` и `opacity: 0` → `1` | 0,20 / 0,30 | 0 | `power2.out` / `power3.out` | 0 |
| Меню, пункты при открытии | Пункты `y: 8` → `0` и `opacity: 0` → `1` | 0,18 | 0,10 | `power2.out` | 0,035, до 5 пунктов |
| Меню, закрытие | Содержимое гаснет сразу в начале закрытия, панель уходит на 8 px вверх, затемнение уходит параллельно панели | 0,10 / 0,18 / 0,18 | 0 / 0,08 / 0,08 | `power2.in` / `power2.in` / `power2.out` | 0 |
| Смена темы и состояния формы | Новые цвета и текст состояния применяются целиком | 0 | 0 | `none` | 0 |

- Hero стартует при готовности HTML и GSAP. Шапка, лид и CTA видимы и доступны с первого кадра. При загрузке страницы с якорем или восстановлении позиции Hero сразу в конечном состоянии.
- Вход секции запускается один раз по `start: 'top 88%'`. Тарифы, поля формы, основной текст и ссылки бронирования видимы сразу. При клавиатурном фокусе анимация соответствующей карточки сразу завершается. Скрытые стартовые состояния применяются только после инициализации JS.
- У фото вкладок зарезервирован единый размер. Текст и кнопка обновляются по выбору, фото начинает переход после декодирования. До этого сохраняется предыдущее фото, а при ошибке показывается постер новой вкладки. Быстрое переключение приводит к последней выбранной вкладке. Клавиатура: стрелки, Home и End перемещают фокус, Enter или Space активируют вкладку.
- Меню открывается как диалог. При открытии переносим фокус внутрь, при закрытии возвращаем на кнопку. Escape закрывает диалог. Смена темы и навигация работают с клавиатуры.
- Скролл-сцена **«Внутри клуба»** — единственное закрепление. Включается от **1200 × 760 px** при точном указателе, hover и обычной настройке движения. `start: 'top top'`, `end: '+=140%'`, `pin: true`, `pinSpacing: true`, `scrub: true`, `snap: false`. Дистанция `end` равна 1,4 высоты области прокрутки. Фазы по прогрессу: `0–0.24` — корт, `0.24–0.34` — переход, `0.34–0.66` — игра, `0.66–0.76` — переход, `0.76–1` — после матча. Таймлайн нормирован до `1.0`. У обоих переходов `duration: 0.10` **единицы таймлайна**, `delay: 0`, `ease: 'none'`. Новое медиа входит снизу под маской внутри неподвижной рамки. Подпись меняется в середине перехода. Скорость задаёт пользователь. Кадры и подписи вне режима закрепления идут последовательно в обычном потоке.
- При `prefers-reduced-motion: reduce` состояния применяются мгновенно, скролл нативный, Hero показывает постер, сцена «Внутри клуба» раскрыта в потоке. Hero с автоматическим видео имеет видимую кнопку паузы. Если видео не воспроизводится, остаётся постер. Движение работает через `transform`, `opacity` и маску медиа. Глобальный snap, плавающий курсор, прелоадер на весь экран, bounce и параллакс для текста исключены.

Справка: [GSAP Easing](https://www.gsap.com/docs/v3/Eases/).

## 5. Сетка, медиа и бронирование

| Параметр | ≥ 1200 px | 768–1199 px | ≤ 767 px |
| --- | ---: | ---: | ---: |
| Колонки | 12 | 8 | 4 |
| Межколонник | 24 px | 20 px | 16 px |
| Поля контейнера | 48 px | 32 px | 20 px |
| Вертикальный отступ секции | 112 px | 80 px | 56 px |
| Высота шапки | 72 px | 64 px | 56 px |

Максимальная ширина контента между полями — 1440 px. Базовый шаг отступов — 4 px. Скругление медиа и карточек — 16 px, полей и кнопок — 8 px. Минимальная зона действия — 44 × 44 px. Основная кнопка высотой от 48 px. У каждой секции максимум один основной CTA. Карточки и меню строятся из тех же токенов в обеих темах.

1. **Hero.** На десктопе текст занимает колонки 1–6, медиа визуально доминирует в правых 7–12, факты о локации стоят справа внизу. На планшете — две зоны по 4 колонки. На мобильном — шапка, H1, одна строка лида или две короткие, кнопка и затем медиа. Основной CTA полностью виден при 360 × 640 px в масштабе 100%. При увеличении шрифта блок растёт по содержимому. От TWICE берём кадр и масштаб заголовка, от Baztan — раскрытие медиа маской и привязку к месту.
2. **Первый визит.** Три вкладки: «Забронировать», «Найти партнёра», «Что взять». Текст слева, действие рядом, фото ниже в фиксированной рамке `16:9` на десктопе и `4:3` на мобильном. От Padel Friends берём понятный порядок действий и мгновенную смену инструкции. При недоступном JS все три шага читаются как последовательные блоки.
3. **Корты, цены и бронирование.** В одном потоке показываем параметры кортов, тариф и переход к выбору времени. Доступный слот содержит дату, время по Казани, длительность, корт и итоговую цену. При пустой выдаче показываем ближайшую доступную дату, если она известна, и действие «Изменить дату». При ошибке связи — «Повторить» и контакт клуба. Внешняя форма открывается по настоящей ссылке, рядом указан способ связи на случай недоступности сервиса.
4. **Внутри клуба.** Три реальных сюжета для сцены из раздела 4. Широкий кадр корта, средний план игры, люди после матча. От Buenas Open берём чередование масштаба и живые моменты между розыгрышами. От TWICE — неподвижную рамку с меняющимся содержимым. При отсутствии полного набора кадров используем доступные фото в обычном потоке.
5. **Как добраться.** Подтверждённый адрес, ориентир, вход и информация о парковке доступны текстом. Маршрут открывается по ссылке «Построить маршрут». Визуальный акцент в духе Baztan — линия пути от ориентира ко входу, если этот маршрут подтверждён клубом.

## 6. Приёмка

- Проверяем ширины **360, 768, 1024 и 1440 px**, мобильный первый экран при **360 × 640 px**, режим закрепления и его отключение на низком окне. При увеличении текста до 200% контент остаётся доступным и переносится без горизонтальной прокрутки страницы.
- Проверяем обе темы и все состояния CTA, видимость фокуса поверх медиа, клавиатурное меню и вкладки, прямые якоря, возврат назад, тач и уменьшенное движение.
- Проверяем полный маршрут до подтверждения брони, пустую выдачу, ошибку связи и повтор. При отключённом JS остаются читаемый контент, контакты и рабочая ссылка бронирования.
